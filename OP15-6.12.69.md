# Build OnePlus 15 ColorOS: Android16 6.12.69, KMI 6, 4KB

The stock version supplied for this device is
`6.12.69-android16-6-g242e1a071878-ab15865446-4k`.
Google's build **15865446** is tagged **android16-6.12-2026-03_r54** and
uses commit **242e1a07f8782987c579929a20a74c0b26e88608**. The supplied short
hash differs by one character, so verify it on the phone if exact provenance
is required. The source has Linux 6.12.69 and KMI_GENERATION=6.

Source: <https://android.googlesource.com/kernel/common/+/refs/tags/android16-6.12-2026-03_r54>.

## Run the build

1. Commit and push the new workflow, manifest, and patch preparation script to
   your GitHub fork.
2. Open **Actions → Build OP15 6.12.69 Android16 KMI6 → Run workflow**.
3. Select **KSUN-SUSFS** for KernelSU-Next and SUSFS v2.3.0,
   **KSUN** for KernelSU-Next alone, or **stock** for an unmodified GKI baseline.
4. After a successful run, download **AK3_OP15_android16-6.12.69_KMI6_4k_…zip**
   or **Image** directly from the run's artifacts.

Successful builds upload only the AnyKernel3 ZIP and Image as two separate
files. Each upload uses [`actions/upload-artifact@v7` with `archive: false`](https://github.com/actions/upload-artifact/blob/v7/action.yml),
so there is no outer ZIP to extract. Retention remains seven days.
Failed runs upload logs, the generated configuration when available, and
source information in a separate `OP15-build-failure-…` diagnostic archive.
The workflow does not publish a GitHub Release.

Source downloads retry transient fetch failures and allow three sync attempts
in the same checkout. Projects already fetched at their pinned revisions are
reused; later attempts reduce parallel downloads to one. Each attempt is
limited to 30 minutes. The failure diagnostic archive includes
`source-sync.log` when source synchronization fails.

The hosted-runner job removes unused SDKs, tool caches, and Docker images
before installing its dependencies. Swap is limited to 4GB instead of 16GB
to leave more disk space for source archives and build outputs. Cleanup
runs only on GitHub-hosted runners. The workflow requires at least 45GiB
free after setup and 12GiB before compilation; these checks fail early
instead of starting a large stage with too little space. They are reserves,
not a guarantee against every possible source-download failure.
`disk-space.log` records free bytes, free inodes, and major build-directory
sizes, including on a failed job while the runner is still operational.

## Why use this workflow

The existing `configs/a16/OP15.json` points to OnePlus's source for
**6.12.23 / KMI 5**. Its `kernel_version` remains `6.12`: this field selects
the kernel family and SUSFS branch. Changing it to `6.12.69`, or changing
SUBLEVEL in Makefile, does not upgrade the source or its KMI.

The new GKI manifest pins all 50 source/toolchain projects using Google's
superproject **9c65188d7ddf2d3dbc63f5cca6da01d13331b400**, which references
the r54 common kernel. The workflow uses the corresponding Kleaf builder
and keeps MODVERSIONS and the Android KABI code intact. For root builds,
it disables the stock defconfig equality check and symbol trimming so
KernelSU can be built into the image.

LTO is disabled because this r54 source requires `!LTO` for
`CONFIG_GENDWARFKSYMS`. ThinLTO selects the older genksyms mechanism, so it
must not be used to build this Android16 kernel for the stock modules.
The packaging step checks the generated configuration for MODVERSIONS,
GENDWARFKSYMS, and the selected root features.

The pinned Kleaf distribution target accepts `--destdir` to export its
outputs. Its symbol table is named `kernel_aarch64_Module.symvers`; the
workflow also provides it as `Module.symvers` in the runner's output directory.
The generated kernel configuration is uploaded with failure diagnostics.

## Local build validation

On October 14, 2026, the pinned KSUN-SUSFS sources were built successfully
on Ubuntu 24.04 under WSL2. Kleaf completed its build and symbol-list checks,
and the distribution outputs were packaged into an AnyKernel3 ZIP. The
ARM64 header, 4KB page size, MODVERSIONS, GENDWARFKSYMS, KernelSU and SUSFS
configuration, ZIP integrity, and SHA256 checks all passed.
The resulting release is `6.12.69-android16-6-maybe-dirty-4k`, with
KernelSU-Next v3.4.0 (33326) and SUSFS v2.3.0. This validates the local
KSUN-SUSFS build; a GitHub-hosted run and device boot still require testing.

## Source and patch compatibility

KernelSU-Next, SUSFS, the integration fix patches, and AnyKernel3 are pinned
to explicit revisions. The SUSFS revision predates the October 12 enable
patch changes, which do not match the pinned KernelSU-Next fix patches.
Two patch context adjustments accommodate r54's dma-buf header and
`vma_data_pages()` helper, preserving the upstream code.

The new workflow omits the older OnePlus module overlays and optional
performance, BBG, Droidspaces, and NTSync patches. Matching the stock GKI
base is the starting point for compatibility; it is not a device boot test.
Keep the phone's original boot image available before testing an artifact.

The **OP15** choice added to the original multi-device workflow selects
only its existing OP15 configuration, which still builds the older source.
Use the dedicated workflow above for **6.12.69 / KMI 6**.
